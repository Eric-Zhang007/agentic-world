# Persistent whitebox milestone, October 9, 2026

This milestone tests agent-authored executable worlds before H3. It does not
claim a faithful single-image reconstruction or new ControlNet integration.
Source is the previously H3-generated 1024x768 scene, not real gameplay.

## Implemented

- Standalone Godot 4.5 runtime, procedural terrain and real 3D preview rendering.
  Terrain parameters and seed remain persistent. Box, stairs, actor and staff
  resources are described in `configs/whitebox_resources.json`.
- Agent writes actual scene/action JSON through the existing GPT gateway;
  initialization is not limited to four objects. The tested scene has 15 entities.
- Actors have a 15-point coarse rig, two-bone arm/leg IK, procedural gait and
  terrain-aware support-foot targets. Staff has two endpoints, two grips and an
  explicit horizontal angular trajectory. Contact events are sampled proxy
  geometry, never automatic real contact, damage or victory.
- Visible guard faces/tracks/maintains distance and strafes; offscreen patrol
  retains its waypoint progress. Both run on the same clock regardless of camera.
- Reuses `WorldDB`: persistent entities plus metadata/history, not a second
  authoritative scene database. Godot Y-up maps to existing Z-up as [x,-z,y].
  Engine documents and timeline files are derived snapshots/candidates.
- Commit requires numerical and agent visual acceptance. The candidate is
  deterministically recomputed from the locked committed revision before writing.
  Scene creation and first action commit are atomic. Static changes, identity
  changes and stale candidates are rejected.
- Appearance memory stores immutable source frames/crops and matching prompts,
  indexed by object/view/state. Originals remain identity anchors; unaccepted
  generated references cannot replace them. This episode keeps three original
  object references; where no crop was proposed the full frame is retained with
  the object description. `appearance/request.json` is prepared, not sent to H3.
- Explicit `reconcile` CLI allows creative additions with provenance/reasons.
  Conservative accepted-camera/path checks reject historical contradictions.
  Transform/terrain rewrites after acceptance require regeneration or a future
  explicit rollback workflow. Full historical branching is not implemented.

## Real execution

Server: `/home/star/agentic_world/outputs/whitebox_persistent_20261009`.

The agent first authored a temple courtyard with stairs, walls, terrace,
monument proxies, two visible combatants, held staff and a creative patrol NPC.
Early runs were rejected for mirrored actor ordering, uninitialized staff in
setup views, grounding ambiguity and insufficient offscreen visual evidence.
These rejected proposals/videos remain in `whitebox_agent_20261009` and
`whitebox_agent_verified_20261009`. Their worlds were not committed.

Fixes included initialized rig/grips, terrain-relative feet with visible soles,
chronological patrol closeups and the agent's own camera/layout repair. The
accepted run replays that saved agent proposal through the corrected executor;
it is not an independently re-sampled scene or a hand-authored replacement.

First accepted action: sidestep, horizontal sweep, recovery, 75 frames at 24 fps
(3.125 seconds). Second real agent request: backward step and ready hold,
60 frames (2.5 seconds). Both received ACCEPT and passed numerical checks.
Persistent world time is 5.625 seconds at revision 2. Both NPCs continued to
move; the patrol visibly turned while preserving its route state.

Read-only checks and exact values are in `audit.json`. It checks persistent IDs,
static entity equality and terrain equality across the two actions. The guard
is not a sophisticated combat AI. A full source-to-world metric depth/pose
calibration has not been established; matching source left/right topology is
not proof of metric reconstruction.

Measured audit: 15 entity IDs preserved; static geometry and terrain compare
equal; two committed history entries; three appearance references. The second
action's maximum hand-to-staff-axis distance is 2.29e-16 world units and support
sole clearance range is [0,0] at sampled frames. These metrics describe our proxy
execution, not inferred real anatomy or H3 accuracy. The first report predates
those extra aggregate fields; it is retained unchanged rather than backfilled.

## Commands

```bash
cd /home/star/agentic_world
.venv/bin/python scripts/whitebox_cli.py create \
  --image outputs/h3_scene_20261008/frame_011.png \
  --output outputs/new_whitebox \
  --goal 'Build the courtyard. Sidestep, sweep once, recover. NPCs act independently.'
.venv/bin/python scripts/whitebox_cli.py act \
  --output outputs/new_whitebox --goal 'Step backward and hold guard without attacking.'
.venv/bin/python scripts/whitebox_cli.py inspect --output outputs/new_whitebox
.venv/bin/python scripts/audit_whitebox_episode.py outputs/whitebox_persistent_20261009
```

`create --proposal saved/agent_proposal.json` replays an agent proposal for
executor regression tests. `--attempts` bounds repair attempts. Failure leaves
NOT_COMMITTED status and all review evidence, not a fabricated success.
`reconcile --edits edits.json --reason '...'` takes an explicit list of
`{op:spawn,entity:{...}}` operations. Existing dynamic motion belongs in `act`.

Every attempt saves proposal, initial scene, action, timeline, numerical report,
candidate world, multi-view PNGs, full whitebox MP4, NPC closeups and agent
visual review. Accepted attempts also export appearance prompts/references.

## Dependencies and tests

Godot and private Xvfb libraries were downloaded as standalone runtime assets;
no system package installation, Python environment upgrade or H3 weight change.
Godot uses software OpenGL under a private X display, not the H3 GPUs. Details
and runtime commands are in `whitebox_engine.md` (local workspace `docs/`).

New regression coverage includes rejected commits, stale/tampered candidates,
initialization rollback, null behaviors, camera inputs, overhead clearance,

compileall passed. GPU utilization was 0% on all four devices after completion.

## Remaining scope

Stairs currently have conservative box collision, not walkable step physics.
There is no navigation mesh, jumping, ragdoll, destructibility, damage model or
arbitrary articulated asset import. Collision and contact are bounded sampled
approximations, not exact continuous collision detection. Procedural gait can
slide feet; this is not production character animation. Rig proportions and
geometry are simplified. Visual review is sparse and fallible.

The new whitebox has not been conditioned into H3 yet. Depth/semantic exports,
multi-reference H3 binding and video-to-whitebox reconciliation remain a next
integration stage after user acceptance of the whitebox behavior itself.
