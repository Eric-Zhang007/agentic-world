# GTA 单图建模与连续闭环实测

本轮从本地 GTA 数据集选择乡镇路口、城区砖路和港口车辆三个场景。
Agent 使用真正的 Pi 会话，模型沿用现有配置。初始化只提供 RGB 图；
数据集配对白模、相机和世界 JSON 留在本地，用于事后对照。

## 单图建模

三组都生成了可执行场景、完成自查并初始化 SQLite 世界。
从首个模型回复到初始化任务结束，乡镇约 316 秒、城区约 294 秒、港口约 326 秒。
每组允许最多三轮预览和 25 个粗实体；这是本轮快速初始化预算，不是模型能力上限。

当前结果能建立主要人物、道路方向和部分建筑地标，但尚未达到数据集白模的背景完整度。
城区保留了路灯、红色路缘、停车亭、两个人物和远处建筑；街道汇聚方向、建筑轮廓仍有偏差。
港口保留了两名行人、车辆块体、起重机和集装箱，但车辆缺轮廓部件，起重机和建筑过于简化。
乡镇保留了两人、商店和路旁树干，远景、道路边界与植被覆盖不足。
数据集白模本身的人体姿态也很粗，不能作为精确姿态真值；它的优势主要是背景几何与场景覆盖。

对照图位于 `outputs/gta_pi_loop_20261102/reconstruction_comparison.jpg`。
从左到右是 RGB、数据集白模、Agent 单图白模。Agent 没有读取中间一列。

## 数据中确实存在的资产

完整地图在：
`E:/GTA_555_complete_rebuild_20261025/source/data/worlds/gta5_scene_v3_20260908/`。

- `static.sqlite3`：placements 和空间范围索引，保存模型名、实例变换、边界及来源。
- `placements.jsonl.gz`：静态实例原始记录。
- `collision/`：碰撞网格索引、原始三角形归档、材质和水面信息。
- `heightmap.json`：高度信息，当前配套白模主要使用碰撞表面。

三个样本所在区域分别登记了 2439、3011、1141 个静态候选实例，以及约 31 万、46 万、36 万个碰撞三角形。
这些是区域范围内的候选和几何统计，不是画面里可见物体数量。
源代码还带有 `wm_engine/world/static_store.py`、`world/collision.py` 和车辆路径控制模块，可以复用。

现有 Agent 白模仅支持 actor、box、staff、stairs 和单层程序化高度场。
建筑用盒体替代会丢失门洞、廊道和内部可通行空间；单层高度场不能表达桥面与桥下的两层地面。
车目前只能用静态盒体组合，没有车辆运动和座位关系；植被缺少树干/树冠资源。
数据使用 Z-up，执行白模使用 Y-up，需要明确坐标基和局部原点转换。
数据相机使用屏幕射线，当前相机使用透视 FOV，二者也不能直接当成同一接口。

因此现有资源能用于局部平地行走的粗测试，尚不足以覆盖 GTA 场景的通用漫游和交互。
优先补齐的资源应是可组合的道路/路缘、带开口的建筑立面、树干/树冠、车辆外形与碰撞轮廓，
同时复用已有地图的查询与几何读取代码。

## 闭环测试约定

城区和港口固定使用 1024×576、73 帧、40 步、原生白模视频加 0.5 深度控制。
乡镇另设 512×288、20 步的流程测试；其结果单独报告，不证明高分辨率画质。
首段使用数据 RGB，后续使用实际接受视频的末帧。所有规划、提示词、视频审查和修正由同一个 Pi 会话完成。
每组提供三个事先固定的动作意图，不根据生成结果人工改写世界或挑选接受结果。
每组最多四次生成；部分完成必须从实际状态继续，不跳过动作。

港口基线在生成前发现 NPC 行为接口缺失：初始化的 NPC 巡逻速度为零，主角色动作无法同时改变它的行为。
基线记为失败。后续增加通用 `npc_behaviors` 动作字段，在计划中为非主角色指定巡逻/守卫策略及原因；
模拟不改起点，只有接受视频时才提交结果和策略。旧历史保持不变。
修复后的试验独立记录，不计为原基线成功。

目前深度编码仍是 2 单位以内白、18 单位以外黑；远处建筑不会得到细分的深度值。
它们仍由原生白模视频提供布局信息。这是背景控制的明确限制，未在本轮中途改变编码。

## 已完成的交互试验

港口修复后试验完成 3 次生成、3 段接受，共 9 秒：接近 SUV 并停下、绕到车辆侧面、
在车旁停稳并小幅运镜。每段都由同一 Pi 会话规划、调用 H3、检查图像、提交，再接下一段。
没有人工修改中间场景或接受结论。独立抽帧对照支持粗路径、人物外观、车辆和主要背景连续。
NPC 自然步态、精确三维间距和实际接触仍未充分验证。

乡镇低分辨率基线完成 4 次生成：第一次因主角没移动被拒绝；第二次前进但未停稳，
部分接受；第三次完成停步；第四次粗侧移并轻微运镜。最终接受 3 段、共 9 秒，
只推进了前两个用户动作，最后的路边等待没有在预算内执行。侧移有僵硬/滑步嫌疑。
它验证了失败重试和部分动作续接，不能当成三项交互全部完成。

单图初始化约需 5 分钟，可生成合法、可编译的粗世界。对照数据集白模，建筑轮廓、
道路和植被覆盖明显不足；在本轮最多 25 个实体、3 次预览的预算下，没有达到数据集的白模质量。
这不是精细关节不足的问题，主要缺口是场景资源和几何覆盖。

所有已接受轨迹都仍包含计划支持的粗三维估计。本轮已出现末端运动状态修正，
但尚未出现并验证明显位置偏离后的根轨迹重建；也未测试抓取、掉落或攻击接触。
不要把世界状态接续检查通过写成精确视觉空间校准通过。

## 工具交互改进

基线运行中发现两类额外调用：猜测最后一帧文件名，以及提交时漏写运动状态。
本地改进令 plan/inspect_video 直接返回必填 actor/motion IDs 和实际最终帧索引；
compile 返回实际首尾白模图路径，inspect_video 返回时间拼图和首尾 RGB 图片内容。

两个 Python 回归测试通过，实际 Pi TypeScript 扩展边界的图片测试通过。
在服务器独立 `harness/pi_review_probe` 中，真实模型只调用一次 inspect_video，收到三张图片，
随后独立识别了乡镇片段“已经前进，但未清楚停稳”。没有读原审查结论，也没有修改世界。
证据：`outputs/gta_pi_loop_20261102/review_interface_probe.json`。

## 最终结果与部署

| 试验 | 新生成次数 | 接受历史 | 交互结果 |
|---|---:|---:|---|
| 城区 | 3 | 3 段 / 9 秒 | 前进、侧移并小幅运镜、返回路灯附近；NPC 冻结跑姿仍在 |
| 港口修复后 | 3 | 3 段 / 9 秒 | 接近车、绕车角、车旁停稳并小幅运镜；粗路径和外观连续 |
| 乡镇低分辨率基线 | 4 | 3 段 / 9 秒 | 一次拒绝，一次部分接受；前两项动作粗完成，第三项未执行 |
| 乡镇独立续接 | 1 | 继承 3 段后共 4 段 / 12 秒 | 实际前进后停住，但尚未到路边；部分接受，保存剩余目标 |

共进行了 11 次新的 H3 生成，10 次接受、1 次拒绝；分支继承的历史不重复计数。
三组初始化和后续规划/审查由 Pi 内的同一配置模型完成。外层 Codex 不编辑中间动作、
场景或审查结果，独立检查视频和修复通用接口。港口 NPC 接口修复和乡镇图片接口续接
分别标注，不混成未经修改的同一基线。

高分辨率每次 H3 约 19 分钟，低分辨率约 3 分钟。完整 agent 工作还包含多轮规划、
白模预览、软件渲染编译和读图；这套流程目前不具备即时交互速度。
`runtime_audit.json` 保存每个阶段的工具调用、错误、模型回合跨度和网关报告的 token 用量。

所有试验结束后，已把以下修正部署到服务器正式 `harness/pi`：

- 实际首尾路径、review contract，以及直接返回拼图和首尾图的工具接口。
- 启动器将当前 Python 环境放入子进程 PATH；真实 Pi 原生 bash 工具验证返回
  `/home/star/agentic_world/.venv/bin/python`。
- 运动评估允许为其他已有角色补充观察，仍要求必填角色、拒绝重复/不存在的 ID。
  原始失败记录在本地和服务器临时分支回放通过，NPC 评估被保存，原世界不变。

服务器通过 13 项连续运动测试、18 项视频提交测试，Pi 启动、实际扩展加载和依赖导入检查通过。
本地另通过两个真实视频工具回归测试及实际 TypeScript 图片返回测试。
这些是功能/集成验证，不计为额外的新视频闭环成功样本。

## 本地查看与复核

打开 `outputs/gta_pi_loop_20261102/index.html`。每个案例都有独立视频、连续已接受回放、
白模/RGB 对照和段落边界帧。没有通过剪辑、跨段插帧或混合去掩盖生成跳变。
段落边界参考路径正确，但实际生成首帧存在重绘差异，所以不是逐像素无缝接续。

```powershell
python -X utf8 scripts/report_gta_pi_loop.py
python -X utf8 scripts/export_gta_accepted_rollout.py
python -X utf8 scripts/audit_gta_video_boundaries.py
python -X utf8 scripts/replay_gta_npc_motion.py
```

本轮确认的是 9–12 秒的小范围移动、绕障碍、小幅运镜和部分动作续接。
长时间重访、大幅运镜、拾取/掉落/接触事件，以及自动外观记忆选择尚未在这条 Pi 闭环中证明。
下一轮优先补 NPC 行为与自然步态验收、利用数据资产补齐路缘/车辆/建筑粗资源，
再用真实关键交互验证状态变化，而不是继续增加精细关节约束。
