# 大圣四界游：同一根棍，同一个世界

2026-10-13。本地预制作；服务器停机，未进行新的 GPT/H3 rollout。
本方案不是已实现功能，也不是已通过的长时序测试。

## 核心创意

大圣从黑神话山寺出发，穿过洛圣都街头、蒙德丘丘人营地和末地，
最后回到同一座山寺。大圣、金箍棒、随身信物具有跨区域不变的 ID。
环境可改变画风，人物服装、脸部、身形与武器身份先保持不变。
结尾镜头重复开场构图，再移动到侧面检查场景确实被保留，而非复用开场图片。

建议完整版本目标 75–110 秒，分成约 15–22 段；这只是预算，不预先判定动作完成。
agent 根据实际视频决定继续、修正或重试。先做 20–30 秒黑神话→另一世界→黑神话的记忆验收，
通过后扩展四界。字幕、地图、等级面板由后期依据已提交事件生成，不让 H3 画字。

## 一份世界状态

`input_data/crossover_demo/world_brief.json` 是预制作规格，不可直接当现有 scene schema 导入。
四个区域占据同一全局坐标系的不同位置；局部参考图、地形种子、NPC 和资源均有 region ID。
只用一个 authoritative DB、一条世界时间线和一个主角。离开区域不删除对象，返回不重新初始化。
区域原点与尺寸是 AGENT_CREATED 的规划值，不能标作从截图恢复的精确位置。

传送门是明确的离散事件，记录源区域/位姿、目标区域/位姿与时间；门前后分别是连续段。
不要求 H3 在一个镜头内完成四种空间风格的连续形变。切换地点可以剪辑，但剪辑不能替代事件。
世界在离屏期间保留静态状态，NPC 按各自策略推进；无视觉证据的变化标为模拟。

## 分幕与检验

| 幕 | 候选动作与画面 | 实际需要证明什么 |
| --- | --- | --- |
| 黑神话出发 | 绕过石台，从台上拾取信物，虎守卫侧身注视，棍尖开启门 | 原始场景锚点、持棍、信物归属；开场保存宽景及左右视角 |
| GTA 街头 | 大圣从停放跑车旁现身，绕混凝土护栏，挡开街头敌人后取回一枚通行物 | 绕障位移、一次明确交互，车辆只作静态代理，避免先做驾驶物理 |
| 原神营地 | 丘丘人举盾逼近，大圣绕盾侧打一棍；盾落地后再拾取战利品 | NPC 独立行为、攻击接触、掉落/持有关系和拾取先后；没有证据就不判胜 |
| 我的世界 | 龙绕柱盘旋，大圣避开吐息，破坏水晶，龙俯冲后落地，再完成决胜动作 | 空中轨迹和阶段状态，水晶状态先于后续战斗；不把整个屠龙压成一个 5 秒镜头 |
| 返回黑神话 | 同门回到山寺，虎守卫仍在执行其策略；放回信物，展示沿途战利品，绕石台收棍 | 同一场景和角色，不重置历史；新增战利品有来源，旧信物不是新生成的替身 |

若末影龙战斗尚不能验证，就保留为未完成遭遇并继续动作，不能配字幕伪造击杀。
升级采用 demo 自定义里程碑，和各游戏原版数值无关；必须绑定实际接受的交互事件。
创意可以宏大，验收不放宽：是否命中、是否掉落、是否击败分别判断。

## Meta 资源与建模粒度

- 一次初始化：区域拓扑、传送门、地形 seed/尺度、可走区域、障碍、建筑锚点、角色身份、基础材质描述。
- 参数化资源包：寺门/石台/柱/台阶；路面/人行道/护栏/停放车辆；草坡/营帐/木盾；方块岛/黑曜石柱/水晶/返回门。
- 持续更新：角色 root/朝向/粗姿态/速度、NPC 意图、武器归属、交互对象、龙飞行阶段、掉落、物品、等级事件。
- 交给 H3 丰富：非决定性手脚细节、披挂、毛发、尘土、火花、光照；它们不能悄悄改变命中、位移、持有或事件顺序。
- 现有可复用：terrain、box、stairs、actor、staff、guard/patrol 与接受后轨迹修正。
- 尚需实现：region 编译适配、传送工具、通用物品关系变化、掉落/拾取提交、里程碑事件、粗飞行代理与末地边界。

## 参考图与记忆

下载文件在 `input_data/crossover_demo/references/`，来源、尺寸与失败记录在 `download_manifest.json`。
原图不放大冒充高清。HD 门槛为至少 1920×1080；尺寸达标仍需检查运动模糊、主体占比、HUD、Logo 和画面遮挡。
官方截图和商店素材也可能带宣传 Logo，不能直接当初始化帧。外部图只是风格候选，不是同一场景的其他机位。
不允许把不相关的几张截图伪装成可标定的多视角数据；网页可访问也不等于取得素材再发布授权。

每个区域需要：1 张清晰宽景、2 张关键锚点参考、1 张敌人全身图、1 张道具细节图。
主角需要同一身份的正/侧/背参考；目前尚未备齐这些身份一致的多视角。
先挑图并经 H3 制作干净初始化帧，再由 agent 建模并验收；网页素材只进入 agent 的参考库。
保存两类不可混淆的图：原始身份/场景锚点，以及最近接受的实际视频帧。
每张已接受图记录 object/region ID、时间、视角、可见性、图中状态、对应 prompt 与来源。

H3 默认只接实际支持的当前连续首帧；其他参考由 agent 检索并转成选择性描述。
多图直输必须先通过身份污染对照实验，不能默认打开。尤其禁止把四种画风和多个人物裁剪一起输入。
回访检索原区域宽景、目标机位锚点、主角身份和离开时状态，不只看最后一段末地视频。
不要把最后一帧黑神话画面强行作为目标尾帧，制造看似记住了世界的证据。

## 进入完整 demo 前的验收

1. 记忆修复：同一动作/seed 下对照单首帧、agent 文本记忆、选择性参考；检查全段身份而非仅首尾。
2. 单次往返：黑神话→街头→原黑神话；新生成回访视频，不复用旧视频，不读未来帧。
3. 因果闭环：最小掉落→地面存在→拾取→持有；中途失败不允许跳至规划终态。
4. 龙代理：白模先验收盘旋/俯冲/落地轨迹和镜头，再做单段真实 H3；新 actor 类型不得被默默当人形渲染。
5. 四界连续：每段保存计划、实际视频、修正、事件、下一段初态；不得用独立初始化的四段视频拼接冒充闭环。

回访报告分开检查：身份、武器、已知场景锚点、空间关系、NPC 策略、物品与等级来源、历史未覆盖。
对未改变的锚点做开场/返场同机位对照，对有事件改变的对象检查其预期变化；不要求 NPC 回到初始位置。
再做“近端帧记忆”与“近端帧+持久检索”的对照，保留失败次数、重试成本、原始审查。
一次成功是一个案例的证据；长时序能力还需不同 seed 和回访机位的复测。

## 恢复服务器后的顺序

先修复并验收外观记忆，接着做单区域交互与两区域往返，再扩展龙代理和四界长片。
为 demo 新建分支世界，不能覆盖已有实验世界或历史。最终同时输出成片和白模/视频/事件三栏调试版。
